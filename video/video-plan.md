## 2. 当前系统架构

`app/page.tsx` → `components/club-hub.tsx` 的六个真实页签：`Dashboard`、`OrderDesk`、`WorkerBoard`、`PriceMenuPanel`、`HistoryPanel`、`PayrollSettlementPanel`。`components/Modals/OrderConfirmModal.tsx` 负责接单确认，`FinishOrderDialog` 位于 `club-hub.tsx`。`store/use-club-store.ts` 是客户端 Zustand 状态层，读写 `/api/club`；服务端 `app/api/club/route.ts` 权威校验、生成快照、执行事务，数据由 Cloudflare D1 保存（`db/schema.ts`，Drizzle 迁移）。价格及结算函数位于 `lib/settlement.ts`、`lib/order-presentation.ts`、`lib/order-earnings.ts`、`lib/payroll-settlement.ts`。总览图表使用 Recharts，拖拽用 dnd-kit，界面动效用 Framer Motion。

生产代码与影片分开：所有影片代码、演示快照、截图、声音、输出都在 `video/`。演示只启动本地 Vinext + 隔离本地 D1；不复用 `.wrangler/state` 中可能已有的个人数据。隔离环境通过一次性目录和本地数据库副本创建，录制完成可保留可复现的脚本与无隐私的演示 JSON。

## 3. 真实业务 SOP 与结算口径

1. 管理员在价格表定义护航固定价，或陪玩小时价、可接档位、`single`/`equal`/`tiered` 分配和统一/按档位抽成；可分类到嵌套文件夹。
2. 接单台选服务，输入小时数（若为陪玩）、特殊需求、订单编号、可选临时折扣/抽成，选择空闲且满足规则的打手。`create_order` 把服务名、基础价、小时价、权重、抽成规则、人员与折后订单价冻结为快照，关联打手的活跃工资周期，置订单 `active`、打手 `busy`。
3. 订单可手动换人并逐笔保存转单费记录；未结束前仍属于同一订单。`finish_order` 读取订单快照，逐人输入即时打赏，调用 `calculateSettlementWithTransferFees`，冻结 `worker_order_earnings`、`worker_tip_earnings`、`final_club_income`，然后订单完成、打手回到空闲。
4. 打手订单工资与转单费属于工资周期；个人打赏即时到账，不进待结工资。管理员手动关闭每名打手的独立周期，生成待发工资记录，再标记发放。全时段总览、趋势、接单量占比和个人业绩由已完成订单派生。

### 财务镜头的源码对应

- `calculateOrderBasePrice`: 护航取固定基础价；陪玩取小时价 × 时长（0.5 小时步进，按分取整）。
- `specialRequirementsTotal`: 特殊需求加价汇总。`calculateDiscountedOrderTotals`: `折前总价 = 基础价 + 特殊需求`，`折扣额 = round(折前总价分数 × 折扣基点 / 10000)`，`订单价 = 折前总价 − 折扣额`；订单价参与抽成。无临时折扣时就是基础价加特殊需求。
- `buildPayoutWeights` + `allocateCentsByWeight`: 单人 100%，双人平分各 50%，按档位分采用服务设定的 1档/2档权重。整数分按最大余数法补齐分摊余数。
- `getCommissionRate`: 若订单快照存在临时统一抽成就优先；否则按档位/娱乐陪玩专属比例或统一比例。
- `calculateSettlement`: **先按权重把折后订单价分给每名打手作为计算基数；再各自扣对应比例抽成**。每人订单工资 = 自己的价款份额 − 自己的抽成；俱乐部收入 = 各人的抽成相加；最终到手 = 订单工资 + 个人即时打赏。打赏不参与抽成。
- `calculateSettlementWithTransferFees`: 转单费追加到收款打手工资，保留各笔历史，俱乐部抽成不因转单费减少；转单费不是打赏。
- `settleWorkerPeriodOnServer` 使用 `workerOrderEarningForOrder` 汇总本打手的订单工资（含其转单费）并冻结到结算记录；打赏仅在记录明细中作为附注，不计入 `total_amount`。结算周期按打手独立，已结算一人的双人订单并不自动锁住另一人。

主算例使用本地数据库内由 `ensureSeeded()` 写入的**演示套餐**“护航双排”与演示打手“牧野”“北辰”：¥360，统一抽成 10%，两人各占 50%。调用现行 `calculateSettlement` 后，订单份额各 ¥180，抽成各 ¥18，订单工资各 ¥162，俱乐部 ¥36；若演示给每人 ¥20，即时打赏合计 ¥40，最终收入每人 ¥182。它与仓库内 `order-demo-equal` 的历史演示金额吻合；画面角标始终标“本地演示数据”。工资周期里显示每人 ¥162 而不是 ¥182。若使用临时折扣/转单费支线，则须由同一函数实时生成对应数字，不混入主算例。

## 5. 视觉、镜头与声音执行规范

- 画面：#090A0D 的真实站点深灰底，白、#007AFF 蓝、#64D2FF 青、#30D158 绿；橙色只用于即时打赏。依据真实 UI 重绘图标/卡片，屏幕 UI 尽量来自隔离本地站点高分辨率抓取，并与矢量数据图结合。不要把截图当成完整镜头。
- 动画：UI 元件短促且轻微越位；数字与线段有不同的减速曲线；镜头推进用长 S 曲线；状态切换短、精确。跨镜头借用同一物体的速度和位置。滚动数字、路径绘制、蒙版、空间缩放与少量景深有功能目的。
- 安全区：主文字距边 ≥96 px；字幕在下方安全区内；每屏文字段落 ≤2 行。汉字使用系统现有的现代无衬线字体，数字 tabular nums。
- 声音：约 108 BPM 的原创程序化环境音乐（合成低频、柔和脉冲、简短和弦）；功能性 click/tick/soft impact 在节点连接、状态改变、数字落定时出现。结算段达到峰值，数据段放宽，结尾渐弱。使用自制声音或可替换音乐轨道，不采用来源不明的成曲。
- 旁白：冷静、纪录片式中文。工程先保留完整文稿、精确时间字幕与可替换语音轨；若不能获得可靠授权的中文 TTS，则交付无旁白母版和单独可录制稿，不能以未授权声音假装成已完成旁白。

## 6. 工程与验证路径

工程目录：`video/src` Remotion 主合成与可复用视觉节点；`video/public/captures` Playwright 对真实页面的截图；`video/public/data` 本地 D1 演示结果；`video/public/audio` 分离的原创音乐、音效与旁白；`video/scripts` 隔离本地 D1 的采集、渲染及验收脚本；`video/output` 两个 1080p/60fps H.264 MP4；另附独立 README、旁白稿、时间码表和字幕 SRT。

主渲染命令 `npm run video:render` 应生成 `video/output/delta-force-club-hub-film.mp4` 与 `video/output/delta-force-club-hub-film-no-voice.mp4`；命令须失败即报错且不返回半成品成功状态。首版完成后逐镜头检查静止超过 4 秒、页面轮播感、字体/字幕溢出、运动连续性、演示数据与源码计算一致性，再复看完整成片并修正。
